## 11. Referral Flow

`{slug}` → capture client (localStorage, rien côté serveur) → `login.html` → inscription/connexion → `POST /referral/attribute` (serveur, authentifié) → `ReferralAttribution` → checkout Chariow → Pulse `successful.sale` → `ReferralCommission`. Normalisation NFKD+minuscule+tirets, slugs réservés dérivés d'une inspection réelle des routes, attribution non falsifiable côté client (dérivée du JWT).

## 12. Financial Ledger

`commission_amount = floor(gross_paid_amount × 4000 / 10000)`. Exemple obligatoire vérifié : catalogue 20 000, réellement payé 15 000 → **6 000** (jamais 8 000). Ledger = seule source de vérité, jamais le prix catalogue quand un montant webhook réel existe.

## 13. Payment State Machine

`CLICK → ATTRIBUTED → CHECKOUT → PENDING → CONFIRMED → COMMISSION`, branches `FAILED` (aucun Pulse jamais envoyé), `CANCELLED` (non modélisé distinctement par Chariow dans ce dépôt), `REFUNDED` (`license.revoked` → `REVERSED`, jamais supprimé). Preuve structurelle + testée : aucune commission avant `CONFIRMED`.

## 14. Idempotence

Webhook (`ProcessedPulseDelivery`), ledger (`UniqueConstraint(source_event_id)`), attribution (`UniqueConstraint(converted_user_id)`) — trois niveaux indépendants.

## 15. Webhook Security

Signature `x-chariow-signature`, HMAC-SHA256, comparaison `hmac.compare_digest` (constant-time). Signature invalide → 401, jamais traité. Payload parsé **après** vérification uniquement. Secret jamais exposé.
