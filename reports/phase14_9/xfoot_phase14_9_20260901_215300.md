## 7. Frontend → API — ANOMALIE CRITIQUE

`PRODUCTION_API_URL = https://api.xfoot.site` confirmé dans le code servi. Aucun `localhost`, aucun secret en dur.

**Mais** : le fichier `api.js` actuellement servi (**3666 octets**, lu intégralement) est la version **pré-Phase-14** — il s'arrête après `getCurrentUser()` et ne contient **aucune** des 4 fonctions ajoutées par Phase 14 : `getOrCreateVisitorId`, `captureReferralFromUrl`, `attributeReferralIfPresent`, `applyRoleBasedNav`. Le commit `ebb23ec` attend 8122 octets.

**Conséquence 1 — Connexion/Inscription cassées** (`login.html:81`) : le script appelle `captureReferralFromUrl();` en haut de la branche « non connecté », **avant** l'attachement du gestionnaire `submit` du formulaire. Cette fonction étant indéfinie, une `ReferenceError` stoppe le reste du script — **le gestionnaire submit n'est jamais attaché**. Le formulaire (sans `method`/`action`) retombe sur une soumission GET par défaut vers lui-même : **email et mot de passe exposés en clair dans l'URL**, aucune authentification n'a lieu.

**Conséquence 2 — Contenu principal cassé sur 11 pages** (`index.html`, `live.html`, `arena.html`, `vip.html`, `history.html`, `billing.html`, `dashboard.html`, `promoter.html`, `admin-promoters.html`, `admin-subscribers.html`, `admin-earnings.html`) : chacune appelle `applyRoleBasedNav();` avant ses fonctions de chargement de données (ex. `loadLeagues(); loadWeeklyFixtures();` sur `index.html`) — la même `ReferenceError` stoppe leur exécution. **Tout utilisateur déjà connecté voit une page vide de son contenu dynamique.**

**Cause racine** : upload manuel **partiel** — `.html`/`.htaccess` mis à jour, `api.js` oublié.

**Correction — non appliquée automatiquement (hors périmètre read-only)** : uploader/écraser **uniquement `frontend-design/api.js`** (8122 octets, commit `ebb23ec`) dans `public_html/`. Aucun autre fichier à retoucher.
