## 1. Identité du Problème

Compte Admin de test créé, email ajouté à `ADMIN_EMAILS` sur Railway, mais `admin-promoters.html` affiche « Accès réservé aux administrateurs. » après connexion.

**Le message exact affiché prouve que le backend renvoie un HTTP 403** (pas 401) — ce n'est ni une session absente, ni un bug frontend.

## 2. Endpoint Concerné

`GET /admin/promoters`, appelé par `admin-promoters.html::loadPromoters()`.

## 3. Code HTTP — Preuve Directe

Code source lu en direct depuis la production :

```js
errorEl.textContent = e.message && e.message.includes("403")
    ? "Accès réservé aux administrateurs."
    : "Impossible de charger la liste des promoteurs — " + (e.message || "erreur.");
```

Ce message précis n'apparaît **que** si `loadPromoters()` a levé `Error("Erreur (403)")` — donc `res.status === 403` confirmé.

**Distinction cruciale 401 vs 403** : `apiFetch()` redirige automatiquement vers `login.html` sur un 401. Cela ne s'est **pas** produit (l'utilisateur reste sur la page et voit le message d'erreur) — **le token est valide, l'authentification a réussi**. Le problème est exclusivement dans `require_admin()`, pas dans l'authentification.

## 4. État Authentification

Session valide (voir §3). Email réellement utilisé : **non déterminable par l'agent** — nécessiterait le token, jamais manipulé (règle absolue). L'utilisateur peut le vérifier lui-même via DevTools → Réseau → réponse de `GET /auth/me` → champ `email`.

## 8. Nécessité Éventuelle de Redéploiement

Le code relit bien `os.environ.get("ADMIN_EMAILS")` à chaque requête (confirmé, jamais mis en cache côté application). **Mais** une variable d'environnement n'est pas consultée dans un magasin externe — c'est un bloc mémoire copié dans le processus **une seule fois, au démarrage**. Modifier la valeur sur Railway ne modifie pas rétroactivement un processus déjà en cours ; celui-ci continue de voir l'**ancienne** valeur tant qu'il n'a pas redémarré.

**Hypothèse principale** : le service Railway n'a probablement pas encore redémarré avec la nouvelle valeur — non vérifiable directement par l'agent.
